When reviewing shell hooks in `.claude/hooks/`, check these specifically (the first one, `docs-consistency.sh`, shipped 2026-06-20 — see [[project-repo-shape]]):

- **Shebang vs invocation shell.** Hooks are invoked by their executable path from `.claude/settings.json` (`$CLAUDE_PROJECT_DIR/...`), so they run under their shebang — but if the exec bit is ever lost, Claude Code may fall back to `sh`. A bash-only construct (e.g. process substitution `done < <(...)`) is a **parse-time** syntax error under `sh`, so a runtime re-exec guard cannot rescue it → exit 2 on every edit. `docs-consistency.sh` keeps `#!/usr/bin/env bash` but its body is deliberately POSIX sh-clean (heredoc-fed `while`, not process substitution), so it parses and runs identically under both shells. **Verify any new hook with `sh -n hook.sh`.** This is the single most likely way a hook breaks editing.
- **Scope gate uses `$CLAUDE_PROJECT_DIR`.** Right for this project hook; the plugin's guards use `${CLAUDE_PLUGIN_ROOT}` instead.
- **`\b...\b` word boundaries are safe against substring over-match** on BSD/macOS grep (`grayscale` does not match `\bgray\b`, `catalogue` not `\bcatalog\b`, `epicenter` not `\bcenter\b`). Verified on macOS BSD grep. The US-spelling wordlist is curated exact-word data and lives only in `.claude/` (out of scope) so it never self-flags.
- **But `\b` next to punctuation is NOT portable.** macOS BSD grep (2.6.0-FreeBSD) treats end-of-line after a non-word char as a word boundary (`echo 'a .' | /usr/bin/grep -E '\.\b'` matches); GNU grep and Python `re` do not. So a pattern like `(\.|-A)\b` behaves differently per platform. Seen 2026-11-22 reviewing the Appendix C git-guard: the old `(-A|\.|--all)\b` blocked `git add .` on macOS but passed it on GNU. Prefer explicit `[[:space:]]`/`$` delimiters around punctuation-bearing tokens.
- **Testing grep here:** in the Bash tool, `grep` is a shell function wrapping ugrep, not the binary a hook runs. Test with `/usr/bin/grep` (BSD). No GNU grep is installed and the container daemons were off (2026-11-22); Python `re` (`\s`, `\b`) is an adequate stand-in for GNU ERE semantics on these patterns.
- **Known false-negative gaps (acceptable, not defects):** plural `Appendices A & C` is NOT checked (regex is `Appendix [A-Z]` with trailing space). Per-file run means a batch adding both a new section and a forward-ref can transiently flag. Both are documented in the script header.
- **Fail-open discipline is correct:** missing jq, empty/malformed stdin, no file_path, non-existent or out-of-repo file, non-markdown, `.claude/**`, gitignored files, `docs/plans/**` all exit 0. A hook that errors/hangs is worse than one that misses — confirm every early-exit path returns 0. The gitignored-file skip itself fails open: `command -v git` guards git's absence and `check-ignore` errors are swallowed, so a non-repo or missing git falls through to the normal scope gate rather than blocking.
- **Scope-gate exclusions must be placed *before* the inclusion gate.** The `git check-ignore` skip and `docs/plans/*` (the latter excluded 2026-06-20, covers `docs/plans/archive/` too since `case` globs span `/`) exit 0 in a gate that runs ahead of the `docs/*|README.md|...` inclusion gate — otherwise `docs/*` would re-include them. When a new exclusion is added, check ordering, not just the glob.
- **Scope drift between the hook and its prose describers.** When the hook's scope changes, *enumerated* no-op lists (e.g. `add-section/SKILL.md` step 4, this file's own fail-open list) drift out of sync, while generic describers (CHANGELOG "on each in-scope Markdown edit", README "on edit") don't enumerate scope and stay correct. After any scope change, grep tracked files for enumerated scope lists and reconcile.
- **Check-count drift.** The hook's header counts its checks (six, A–F, since 2026-11-25; it had lagged at "four" until 2026-11-24), and the README lists them. When a check is added, update both and grep tracked prose for any new count. Checks D, E and F each got a CHANGELOG line and a `feat` commit; ask for the same when a check is added.
- **Check F ("Last updated" is today's; 2026-11-25 shape).** Greps `$stripped`, so backtick fences are skipped but `~~~` fences and inline code spans are not; a date ahead of the local clock passes (timezone skew), so does a subtitle hard-wrapped between "Last updated" and the date. Its spelling-only exception is in the finding Claude reads. Probe with a doc in a fresh `docs/probe-*.md` of the extracted copy.
- **Check C (link resolution) false-positive/negative shape.** Inline `[text](path)` only, extracted via `grep -noE '\]\([^)]*\)'` after `awk`-blanking fenced blocks (line numbers preserved). `[^)]*` stops at the first `)`, so a path containing a literal `)` (e.g. `file(1).md`) truncates → false positive; a path containing a space truncates at `target=${target%% *}` (the title-strip). Neither occurs in this repo's paths, so both are acceptable gaps, documented in header limitation (3). Confirmed safe: multi-link lines (grep `-o` emits each), `"title"`, `#fragment`, bare `#anchor` (strips to empty → skipped), directory targets (`-e`, not `-f`), scheme/absolute/protocol-relative skips. The doc's example-output block matches the hook's real stderr verbatim.

- **Probing an INT trap.** A background job from a non-interactive shell starts with SIGINT ignored, and `kill -INT $pid` on a shell waiting for a child that exits normally just carries on (bash and dash both), so either probe falsely shows "trap not run". Mimic Ctrl-C instead: start the script in its own process group with SIGINT reset (`perl -e 'use POSIX; setpgid(0,0); $SIG{INT}=q(DEFAULT); exec @ARGV' sh script &`) and `kill -INT -- -$pid`. Used 2026-11-24 to confirm all-awks.sh's INT/TERM traps clean its temp dir under dash and sh (rc 130/143).

**How to apply:** run the hook directly with synthetic JSON payloads (`printf '{"tool_input":{"file_path":"..."}}' | bash hook.sh; echo $?`) across these cases rather than reasoning about it. Confirm in-scope dangling refs/US spellings give exit 2 and everything else gives exit 0.
