Defect classes seen in this repo (check these specifically each review). Dates say when a class was first seen.

1. **Changelog lines that over-claim.** Verify each `[Unreleased]` line against the document it describes, including its justification: "as §11 says" needs §11 to say it (2026-11-24).
2. **Pointers whose target doesn't hold the thing.** The README sent readers to `NOTICE` for a clause in `LICENSE` §6; a `(§N)` resolved to a section that never covered the cited convention. Open the target and confirm. After a title change, grep for the *old* title: docs cite each other by quoted title (NOTICE included).
3. **Path or term drift between prose and the live config**, e.g. prose saying `memory/` where `memory: project` resolves to `.claude/agent-memory/`.
4. **Local secrets protected only by the user's global gitignore**, not the repo's `.gitignore` (`settings.local.json`).
5. **Counts and ranges.** Run the grep in `.claude/skills/add-section/SKILL.md` step 2; it covers appendix counts and ritual/skill totals. Lists that *name* the rituals without counting them escape it (the skill says which), so check those by hand when a ritual is added.
6. **Reconciliation claims where one file was missed.** When a diff says it reconciled several files, open each. When it qualifies a repo-wide claim, grep the claim's other phrasings across the tree (`git grep "no build"`), not only the changed lines. The plan-first trigger lives in §2, the §5 matrix "Plan first?" column, Appendix J and `plugin/skills/plan/SKILL.md`. Flag any new `.claude/commands/` file that re-copies a ritual (the repo dropped its copies on 2026-11-23).
7. **ADRs.** Read an ADR's sections against each other (Alternatives vs Consequences). A superseding ADR that paraphrases its predecessor's reason: quote the old words beside the paraphrase (2026-11-24, ADR 0005 vs 0002). An amendment listing what the repo used to have: check with `git ls-tree -r --name-only <commit> <dir>`. The repo never had its own bash or git guard; `.claude/hooks/` only ever held `docs-consistency.sh`.
8. **Naming the gitignored local-notes folder in a tracked file, including this memory.** Allowed mentions: `.gitignore`, and the bare folder name under `exclude_docs` in `mkdocs.yml`. Check `git grep -n` for the path and the commit messages. Use the neutral term "the gitignored local-notes folder". Old commits on `main` still contain the path; that is not a finding.
9. **A ritual reading a convention from one scope while §1 places it in another.** §1 puts personal conventions (commit style) at user scope, so a ritual reading only the project `CLAUDE.md` gives a global setter the default. Also check that prose describing a fallback matches the ritual's own, and that every value a step reads is used later.
10. **Status claims the next release falsifies** ("not yet in a tagged release"): ask where the line gets removed, and keep the expiring clause out of the changelog. Recompute any evidence list a backlog item cites (PR numbers, runs).
11. **Packaging-doc sentences carried into `docs/methodology.md`.** There "the plugin" has no referent (`git grep -n Minnel docs/methodology.md`), and "the plugin docs" reads as the packaging doc. Also check the carried sentence doesn't restate the same §.
12. **Changelog category.** Corrections to content in the last tag go under Fixed; corrections to content still in `[Unreleased]` fold into its Added entry (the DoD's rule). Check with `git show <tag>:<file>`. For each `fix` commit since the tag, find the entry that names its correction.
13. **Backlog items that plan against the repo's invariants**: shipping an artefact only in the plugin (every shipped artefact also appears in its appendix), adding a ritual without moving its counts, a check that ignores §8 deleting shipped lines or a Check E pair, a type-to-SemVer mapping Conventional Commits doesn't give. Grep counts and pairs before accepting an effort tag.
14. **Backlog reorders and reflows.** Positional pointers ("the item below") can invert: `grep -nE '\b(above|below|after|before)\b' docs/backlog.md`. To prove a reflow lost no words, compare word multisets (`tr -s ' \n' '\n\n' | sort`, then `comm -23`).
15. **Condensed or rewritten changelog entries.** Shortening drops qualifiers: a condition, a narrower quantifier ("pushes to `main`"), an order, a subject. Diff old and new entry by entry. After any rewrite, `grep -n '^## ' CHANGELOG.md` and check each release heading appears once and is well formed (a 2026-11-23 splice left a mangled duplicate). A blank line plus an indented paragraph inside a list item makes the whole list loose on GitHub.
16. **Review-cadence carriers.** The re-run clause lives in `CLAUDE.md`, the template and its scaffold copy, §7's bullet, and the `description` of Appendix A and of `plugin/agents/code-reviewer.md`. §2, §4, §10, the DoD and Appendix E state the cadence without it. Compare them word for word when one changes. The antecedent must be "fixes for its findings" (all of them), not "those fixes": grep `those fixes`. The trivial-branch skip is defined only in `CLAUDE.md` (spelling, punctuation, grammar and formatting since `db77fdc`, 2026-11-24); the others defer to it. Reject prose making Accept the actor of the review (§10: `/accept` gates on the DoD and never dispatches the subagent).
17. **A guard's behaviour changes but the stance prose doesn't.** Grep the stance as well as the guard's name: `git grep -nE "commits?, pushes|behind your approval|accidental commit|reviewed by"`.
18. **Retiring a tailored copy for a generic one.** `diff` each deleted file (`git show HEAD:<path>`) against its replacement and account for every repo-specific line: moved, already covered, or dropped.
19. **Plans citing groupings or marks no tracked file holds** (release groups from a chat triage). Record them in general terms or drop them. A dated label fails when several events share the date.
20. **An acceptance grep that matches its own plan** or an `[Unreleased]` line quoting the old string. Run it as written and list every hit.
21. **A new reviewer check its own repo would trip** (an attribution in `plugin.json` flagged as personal data). Ask what the check does when its evidence is out of reach (no network: mark it unverified).
22. **A DoD rule under an item whose trigger doesn't fire when it's needed.** A prohibition belongs under the item the *forbidden* change trips (raising `plugin.json`'s version early trips the Plugin item, not Release). Check stage numbers in incident notes against the plan and `git log -S`.
23. **A Claude Code behaviour claim that matches my memory.** A match isn't verification: test it in an isolated `CLAUDE_CONFIG_DIR` (never the user's config), and mark memory claims "observed" or "inferred". My own inferred note once became adopter guidance and was false (2026-11-23).
24. **Scaffold templates.** Check E makes the D–H skeletons and their scaffold copies match word for word, so a bare `/release` in an appendix lands in adopters' files where the command is `/minnel:release`. Name rituals by role ("the release ritual"). Don't attribute the methodology's `debt`/`chore` rule to Conventional Commits.
25. **A new ritual's procedure, read as a program** (2026-11-24, Appendix P): an input read in a late step can't inform earlier ones; hard-coded paths against "name yours if it differs" conventions; a lifecycle shortcut that skips a §8 step; strict YAML in `description:` (a `: ` breaks Ruby Psych though Claude Code loads it); the "run it when" line against §10's table. Check a new format token against every carrier, this repo's `docs/backlog.md` header included.
26. **A diagram edge that claims more than the prose.** Walk each edge and terminal node against the prose and the tool's docs; a caption shouldn't restate the paragraph above.
27. **Small doc passes** (2026-11-24): a sentence inserted before an "It …" sentence rebinds the pronoun (recurred the same day in a template `<Keep one: …>` option opening "It runs…" right after "check any other fix … yourself"); "but" turned into "so" inverts a cause; a reflow in a Check E pair should run to the paragraph's end so it doesn't just move the ragged break. When a branch uses the trivial-branch skip, read its `--word-diff` for changed connectives, pronouns, qualifiers and negations.
28. **A reframed premise that summarises other sections** (2026-11-24, hooks "alongside CI"): a paired subject ("hooks and a review subagent … move the same checks to the moment of the edit") gives both a property only one has (§7 runs the reviewer once per branch), and "the same checks" outclaims §6's own PostToolUse tier (a quick build or targeted test). Check the subject and quantifier against each section summarised. The house-voice rule's "After:" example still said "Hooks are your CI" then (fixed in f6a0819). Follow-up 1f8672d dropped §7's "no PR reviewer" premise. Carriers of that premise to sweep when the audience widens: the template pair's "There is no second reviewer; this is it." (adopter-facing, so it contradicted §7), §4's roster row (conditional "With no PR reviewer", so it's fine), §7's intro "without a team to catch you", and this repo's `CLAUDE.md` (true for a solo repo). Grep `no PR reviewer|second reviewer|second pair of eyes|without a team`.

30. **A repo-only procedure promoted into an adopter ritual keeps the repo's preconditions.** When a `.claude/skills/` procedure becomes a step of a plugin ritual, run it in a fresh `git init` scratch repo shaped like a scaffolded project. Seen 2026-11-24 (claude/optimistic-kowalevski, `/wrap` step 2 from the retired `close-plan`): `git mv` into `docs/plans/archive/` fails with "renaming … failed: No such file or directory" when the folder is absent (git 2.54), and `/minnel:scaffold` never creates it; this repo always had it. Same review: a step gated on "has passed the Definition of Done" is ambiguous while the DoD's review item is *pending* until merge, and the stage-per-branch rule (Appendix D) wants the close in the branch's last commit, before the review. Check any "passed the DoD" gate against `/accept`'s "passes, or is pending until merge". Re-review (87b2738, one active-plan pointer): a changelog line listed Appendix F among files that "drop the stage count", though F never had one (it *gained* a `plan:` token in Now). When a line says "X, Y and Z drop/gain W", `git show <base>:<file>` each named file for W.

**Why:** these are the quiet ones — §N and appendix-letter refs are usually correct because they're obviously load-bearing; the prose-accuracy and config-drift mismatches are what slip through.
**How to apply:** don't just check that refs resolve — check that descriptive claims (changelog, README, doc-to-doc pointers) are *true* against current file contents. See [[project-repo-shape]].
