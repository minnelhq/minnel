Defect classes seen in this repo (check these specifically each review):

1. **CHANGELOG entries describing things that aren't in the docs.** The changelog is curated prose, easy to over-claim. Verify each [Unreleased] line against the actual document state — e.g. a claimed "at-a-glance block near the top" that doesn't exist as a block.
2. **Pointers to a target that doesn't contain the referenced thing.** A public doc (README) pointing readers at a doc that doesn't contain the referenced rationale — especially when the real content lives in an internal/untracked note. Seen: the licence README sending readers to `NOTICE` for the no-marks clause that actually lives in `LICENSE` §6 (NOTICE only carries copyright + a pointer to LICENSE). Also the *intra-document* variant — a `(§N)` that resolves to a real section which nonetheless doesn't cover the cited convention: §11 attributed the gitignored local-notes convention to §1, but §1 never mentions it (it's a CLAUDE.md convention). So `§N` resolving to a section is not enough — open the section and confirm it actually covers the thing being attributed to it. **Rename-sweep variant:** when a doc's H1/title changes, grep the whole tree for the *old* title string — other docs cite each other by quoted title, not just by path, and those citations strand silently. Seen: harmonising the three H1s to "A File-First Operating Model for Claude Code" left `docs/packaging-as-a-plugin.md`'s subtitle citing the old "A Methodology for Driving Claude Code". (NOTICE intentionally keeps "Claude Code Methodology" as product-name-of-record — not a defect.)
3. **Path/term drift between methodology prose and the live `.claude/` config.** e.g. methodology calls the memory layer `memory/` but `memory: project` resolves to `.claude/agent-memory/`.
4. **Local-config / secrets protection living only in the user's global gitignore, not the repo `.gitignore`.** `settings.local.json` is safe on this machine via `~/.config/git/ignore` but unprotected for any clone.
5. **Incomplete "known carriers" enumerations of the count/range claim.** When a doc claims to *list* every file carrying the `A–O` range or "fifteen" count, run the actual grep and diff it against the list. The add-section SKILL.md listed README/CLAUDE/CHANGELOG/code-reviewer/DoD/plan/project-repo-shape but omitted the per-appendix-file headers (`docs/appendices/{subagents,hooks,skeletons,skills-and-commands}.md` each say "the full A–O index") and `docs/methodology.md:259` ("Appendices A–O"). The index `docs/appendices/README.md` is covered indirectly (step 1 edits it for the entry). An incomplete carrier list in a skill is worse than no list — it gives false confidence and the omitted carriers go stale.
6. **Stale line-number pins in my own memory.** The 06/2026 code-reviewer.md change told me to anchor by heading/symbol not line number, and to date any note tied to today's state. Pre-existing memory still has bare line pins to clean up when next editing those files: `feedback-recurring-defects.md` cites `docs/methodology.md:259` (re-resolve to the heading carrying "Appendices A–O"); `project-plan-archiving.md`'s `~line 85`/`~line 54` are acceptable because they're paired with a stable description and dated to the appendix split. Convert bare pins to anchors as you touch them; don't churn a file just to fix this.

7. **Multi-file reconciliation claims where one file was missed.** When a diff says it reconciled doc A with doc B (or added an item that other docs/intro lines now point at), open *every* named file and confirm the change actually landed in each. Seen 20/06/2026 (feat/doc-site, first review): ADR 0002 §Consequences, the plan Stage 1, and the DoD's own intro ("see the site-build item below") all asserted the Definition of Done gained a scoped MkDocs build check — but no such checklist item was ever added to `definition-of-done.md`. Three forward-references to a referent that doesn't exist. (Re-review 20/06/2026: the scoped "Doc-site build (when touched)" item is now present in the DoD and the three describers are mutually consistent — resolved.) A specialisation of items 1–2: the claim is in the *describing* files, the omission is in the *described* file.
   **Sibling variant — reconcile every *assertion* of an invariant, not just the files the diff names.** When a change weakens/qualifies a repo-wide claim, grep the whole tree for the claim's *other* phrasings; the diff usually fixes the canonical statement and the named companions but strands a paraphrase elsewhere. Seen 20/06/2026 (feat/doc-site re-review): the branch reconciled "no build, no runtime" in CLAUDE.md, the DoD intro, and ADR 0002 (all now say *the source* has no build, the site is an optional build) and even added CI calling itself "first CI in the repo" — but `README.md`'s Dogfooding paragraph still flatly says the repo is "a documentation project (no build or test step …)", unqualified, in the *same file* that now has a "Reading it as a site" build section a few headings up. The paraphrase was pre-existing so it never showed in the diff — grep `git grep "no build"` for all carriers, not just the changed lines.
   **Carrier note — the plan-first trigger lives in four places, and the `/plan` command is the one that drifts.** The "when to plan" criterion is stated in §2 ("Plan only when the task merits it"), the §5 decision matrix "Plan first?" column, the live `.claude/commands/plan.md` (step "Size the task"), and its published Appendix J copy (`docs/appendices/skills-and-commands.md`, also "Size the task"). When the trigger changes, check all four. Seen 20/06/2026 (chore/prose-followups): the diff relaxed §2 and §5 from ">3 files" to "non-obvious approach (refactor/architecture/invariant)" but left `.claude/commands/plan.md` saying "Plan first when the change **spans multiple docs**" — a positive file-count trigger that now contradicts the relaxed §2. Note the asymmetry: the Appendix J copy was *not* stranded, because it keys on trivial-work size ("one-line or single-file change with no invariant in play"), which is compatible. So the live command and its published copy had *diverged* even before this branch — worth a periodic diff of `.claude/commands/*.md` against their Appendix copies. **Re-converged 20/06/2026 (chore/revise-plan-command):** both copies restructured to the same 5-step shape (Explore/Decide/Draft/Challenge/Present) — step 2 *decides* (skip trivial → "say so and stop"; else continue), step 3 *drafts*, removing the old "Otherwise"-in-step-3 double-gate. The live copy keeps its project tailoring (British English, §N/A–O, renumber/re-letter hazard, `docs/backlog.md`'s `## Now (this plan)` pointer); the Appendix copy stays generic and cites the active-plan pointer as (§3). The two are now genuinely parallel, so a future divergence is again worth diffing for. Note the hook does *not* check `.claude/commands/*.md` (out of scope), so the live copy's British English / §N refs are reviewer-checked only.
8. **An ADR contradicting itself between sections.** Effort/cost claims ("reverting is a two-line change") get written in *Alternatives* while *Consequences* lists more to undo, or vice versa. Read an ADR's sections against each other, not only against the files. Seen 2026-11-22 (chore/zensical-site, ADR 0003). Same pass: check "X names the command" style claims in Consequences against each named file — one of three may only name the tool, not the command.
9. **Naming the gitignored local-notes folder in a tracked file — including my own memory.** CLAUDE.md's Conventions section and the user's global rule forbid naming that folder or describing its contents anywhere tracked or in a commit message; the only allowed mentions are `.gitignore` and the bare folder name in `mkdocs.yml` `exclude_docs`. Check: `git grep -n` for the folder's path (and its bare name near `docs`) — hits should be `.gitignore` only, plus the bare entry under `exclude_docs`; also read the commit message. The neutral term in use is "the gitignored local-notes folder/convention". Seen 2026-11-23: this very file had pinned the path in an example (item 2) and needed a follow-up commit. When I write memory, describe the folder in that neutral term, never by path. Earlier commits in history still contain the path; that is not a finding for a new diff (removing it would need a history rewrite of `main`).

10. **A ritual that reads a convention from one scope while §1 places it in another.** §1's context table lists commit style (and similar personal conventions) under the user-level `~/.claude/CLAUDE.md`. When a change makes a ritual (Appendices J–N and their plugin skills) read a convention only from the *project* `CLAUDE.md` and fall back to a default when absent, a user who set it globally gets the default instead. Seen 2026-11-23 (feat/conventions-as-choices, `/release` and `/wrap`). Check any "read X from Conventions" step against §1's scope table. Same review: check that a fallback described in §-prose ("when the project names neither") matches the ritual's own per-line fallback, and that every value a ritual step reads is used by a later step.

11. **Status claims that the next release falsifies, and evidence lists in backlog items.** A README line such as "not yet in a tagged release", paired with a `[Unreleased]` line that repeats it, goes false in the very release that ships the change, and the changelog line then sits under that version contradicting itself. Ask where the line gets removed (the `/release` ritual won't know to) and keep the expiring clause out of the changelog. Separately, when a backlog *why now* cites PR numbers as evidence ("#10, #14, #15 needed a manual run"), recompute the set: diff each merge against its first parent for published-doc paths (`docs/` minus `exclude_docs`) and compare with `gh run list --workflow docs.yml --event workflow_dispatch`. Seen 2026-11-23 (chore/backlog-triage-readme): the cited list missed merges that changed published docs and got no deploy of their own.

12. **Carrying a sentence from the packaging doc into `docs/methodology.md` without its context.** The packaging doc is about Minnel, so there "the plugin" means Minnel and "the plugin docs" means Claude Code's docs. `methodology.md` has not introduced Minnel (check with `git grep -n Minnel docs/methodology.md`), so the same words leave "the plugin" with no referent, and "the plugin docs" reads as the packaging doc that the sentence links to next. Also check whether the carried sentence restates something the same § already says: §10's skills paragraph already explains `disable-model-invocation`. Seen 2026-11-23 (fix/review-guard-claim-compaction, the "Skills vs commands" paragraph in §10).

13. **A Fixed or Changed line about a feature that no release has shipped yet.** The Definition of Done's changelog item says corrections to not-yet-released content stay under *Added*. Before accepting a Fixed/Changed clause, check whether its subject exists in the last tag (`git show <latest-tag>:CHANGELOG.md | grep`, or `git show <tag>:<file>`). Seen 2026-11-23 (fix/review-guard-claim-compaction): the §10 Fixed line was right to be in Fixed (§10's old text shipped in 0.3.1), but its tail "Check E now compares it" described a change to Check E, which is itself still under [Unreleased] Added. Fold such clauses into the Added entry.

14. **Backlog items that plan a change against the repo's own invariants.** A backlog item is a plan in miniature, so check its proposed route against the invariants it would hit. Seen 2026-11-23 (chore/backlog-triage-ritual): (a) an option to ship a ritual "only as a plugin skill" contradicts the packaging doc's "What to package" rule that every shipped artefact also appears in its appendix; (b) a ritual added "with no letter moving" still strands every "five rituals" count (§10 table intro, §10 "Skills vs commands", README, packaging doc, Appendix J–N file header); (c) a check that `/release` compares backlog targets with `[Unreleased]` ignores that §8 deletes a backlog line when it ships, and that the check lives in Appendix M plus `plugin/skills/release/` (a Check E pair) and the live `.claude/commands/release.md`, not in §8 alone; (d) a claimed type-to-SemVer mapping ("`chore` a patch") that no doc states, and that Conventional Commits does not support. Grep counts and pairs before accepting an effort tag.

15. **Backlog reorders and reflows.** Next items point at each other by position ("the title item below", "do it after X"), so a reorder can invert a pointer silently: `grep -nE '\b(above|below|after|before)\b' docs/backlog.md` and check each against the new order. To prove a reflow lost no wording, compare word multisets of the old and new file (`tr -s ' \n' '\n\n' | sort`, then `comm -23` for words only in the old): every old-only word should be one the diff meant to remove. Also check an "X before Y, which change commands" claim against Y's own text; an item can imply a command it never lists. Seen 2026-11-23 (chore/backlog-triage-ritual, the release-order triage).

16. **Condensing changelog entries changes what they claim.** Shortening drops the qualifier, not just the detail. Check each shortened line for: a dropped condition (Appendix M dates the heading in ISO only *for Keep a Changelog*); a widened quantifier ("each push" when `docs.yml` builds on pushes to `main` only, check `git show <tag>:.github/workflows/docs.yml`; "the public docs" when `docs/style.md` names four narrative docs); a lost scope or order ("project rules" where §1 says the project's `.claude/rules/`; "project's or the user's" where the ritual reads project first); a merged subject ("instructions into skills and hooks" where the source says *processing* to hooks); a dropped platform caveat in a security fix (the 0.3.1 git-guard let `git add .` through under GNU grep). Diff old and new entry by entry, and open the file each one describes. Seen 2026-11-23 (chore/backlog-triage-ritual, the changelog simplification). Same review: a repo-only carve-out from a methodology rule (skipping review on trivial branches, against §7's "non-negotiable … before every merge") needs a divergence note where the carve-out lives, as the DoD's HTML comment does. Markdown check for a changelog item that gains a blank line and then an indented paragraph after its sub-list: by the CommonMark rule it renders inside the item, but the blank line makes the whole category list *loose*, so GitHub puts paragraph spacing on every item in that list. No renderer is installed locally (no cmark or pandoc, and no markdown module in `.venv`), so reason from the spec.

**Why:** these are the quiet ones — §N and appendix-letter refs are usually correct because they're obviously load-bearing; the prose-accuracy and config-drift mismatches are what slip through.
**How to apply:** don't just check that refs resolve — check that descriptive claims (changelog, README, doc-to-doc pointers) are *true* against current file contents. See [[project-repo-shape]].
